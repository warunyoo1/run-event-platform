# ทิศทาง UI

หน้าเว็บสาธารณะสำหรับนักวิ่งไทย เน้นค้นหางานและอ่านข้อมูลอย่างรวดเร็ว อ้างอิง RUNRACE ในเรื่องโปสเตอร์งาน วัน สถานที่ และสถานะเปิดรับสมัคร

- สีหลัก: น้ำเงิน `#1666ba`, หมึก `#182b40`, พื้น `#f7f9fc`, ขาว `#ffffff`, เส้นแบ่ง `#dce5ee`, สถานะเปิดรับ `#1d754f`
- ตัวอักษร: Noto Sans Thai สำหรับเนื้อหาและเมนู; Arial สำหรับอาร์ตเวิร์กภาษาอังกฤษและราคา
- โครงสร้าง: เมนู → ภาพบรรยากาศและข้อความแนะนำ → ช่องค้นหา → ประเภท/ตัวกรอง → การ์ด 3 คอลัมน์ → คู่มือนักวิ่ง → footer
- มือถือ: เมนูยุบ, การ์ดคอลัมน์เดียว, ฟอร์ม 2 คอลัมน์, เป้าหมายสัมผัสอย่างน้อย 44px สำหรับปุ่มหลัก
- จุดเด่นอยู่ที่ภาพเปิดและโปสเตอร์เฉพาะงาน ส่วนค้นหาใช้พื้นขาวกับขอบบางเพื่อเน้นความชัดเจน
- รองรับ focus, skip link, label ฟอร์ม, keyboard ของแท็บรายละเอียด และ reduced motion
- ใช้ semantic tokens กลางใน `src/app/tokens.css` สำหรับข้อความ/พื้น/ขอบ/สถานะ/focus; สีของภาพ Hero และ artwork ของแต่ละงานแยกจาก UI ได้ ข้อความรองใช้ `--muted: #52657a` ได้ contrast 6.00:1 บนขาว, 5.69:1 บนพื้นหน้า และ 5.43:1 บนพื้นขั้นตอนที่ยังไม่ถึง
- ข้อมูลวัน/สถานที่และลิงก์รายละเอียดบนมือถือใช้ 14px, label รอง 12px, ช่องกรอกหลัก 16px ปุ่มรอง บันทึก และสลับมุมมองมีพื้นที่กดอย่างน้อย 44×44px
- มุมมองรายการที่ความกว้างไม่เกิน 600px ใช้แถบ artwork สูง 150px เหนือข้อมูลเต็มความกว้าง เพื่อรักษาขนาดตัวอักษร; toolbar เรียงลำดับและมุมมองย้ายไปอีกแถว ช่องวันเกิดใช้วัน/เดือนในแถวเดียวและปีเต็มแถวถัดไป
- Hero ใช้ `next/image` แบบ fill, `sizes="100vw"`, eager และ fetch priority สูง โดยคง crop และ GSAP เดิม มีขนาดภาพตอบสนองจาก Image Optimization API; ตัวอย่าง WebP 640px ที่ quality 75 ได้ 62,256 bytes เทียบกับ JPG ต้นฉบับ 573,091 bytes
- หัวเว็บใช้โลโก้ เมนูหลัก 4 รายการ และงานที่บันทึกในแถวเดียว ความสูงประมาณ 84px บนเดสก์ท็อป; เปลี่ยนเป็นเมนูเปิดปิดเมื่อความกว้างไม่เกิน 1020px เพื่อไม่บีบข้อความภาษาไทย เมนูที่เลือกใช้พื้นฟ้าอ่อน ปิดเมนูได้ด้วย Escape หรือคลิกด้านนอก
- ฟอร์มสมัครใช้พื้นขาว ขอบเทาอ่อน และ stepper สีน้ำเงิน 4 ขั้นตามภาพอ้างอิง ช่องกรอก 3 คอลัมน์บนจอใหญ่, 2 คอลัมน์บนแท็บเล็ต และ 1 คอลัมน์บนมือถือ พร้อม label, error ใกล้ช่องกรอก และสรุปข้อผิดพลาดที่นำโฟกัสไปแก้ไขได้

ทบทวนคำแนะนำจาก ui-ux-pro-max สำหรับ running events: ใช้พลังของภาพและสีในอาร์ตเวิร์ก แต่ปรับระบบสีจากส้มเป็นน้ำเงินให้ใกล้เว็บอ้างอิง และใช้ฟอนต์ไทยแทนฟอนต์แนะนำที่ไม่ครอบคลุมภาษาไทย ไม่ใส่แอนิเมชันอัตโนมัติในรายการงาน

## Motion

- ใช้ GSAP และ `@gsap/react` โดยผูก scope กับ component และ revert เมื่อเปลี่ยนหน้า/เปลี่ยนสถานะ
- หน้าแรกใช้ timeline เดียว: ภาพซูมกลับเล็กน้อย ข้อความเปิดเข้า และช่องค้นหาตามมา รวมประมาณ 1.1 วินาที
- ผลค้นหาเปลี่ยนเป็นกลุ่มเดียวใน 280ms ไม่ไล่แอนิเมชันทีละการ์ดทุกครั้ง
- เมนูมือถือเปิด/ปิดแบบย้อน timeline ได้ จึงไม่กระตุกเมื่อกดเร็ว และคืน inline style เมื่อกลับขนาดเดสก์ท็อป เมนูที่ปิดเป็น inert
- ขั้นตอนสมัครใช้ opacity transition 300ms เฉพาะตอนเปลี่ยนขั้น ไม่ขยับตำแหน่งช่องกรอกและไม่เล่นใหม่ขณะพิมพ์ข้อมูล
- เลื่อนไปส่วนค้นหา/ขั้นตอนฟอร์มด้วย ScrollToPlugin และ autoKill หยุดทันทีเมื่อผู้ใช้คลิก หมุนล้อ หรือใช้ปุ่มนำทาง ยกเลิก tween เมื่อเปลี่ยนหน้า
- ใช้ ScrollTrigger กับส่วนคู่มือนักวิ่งเพียงครั้งเดียว ไม่เปลี่ยนกลไก scroll ของเมาส์หรือ touch
- `prefers-reduced-motion` ปิด motion และตอบสนองต่อการเปลี่ยนค่าระหว่างใช้งาน เนื้อหามองเห็นได้ตามปกติเมื่อ JavaScript ยังไม่เริ่ม
